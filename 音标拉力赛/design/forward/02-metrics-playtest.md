**关键缺口（本派单已指明，盘点确认）**：
1. `EP02.bestAcc` 只存**历史最大值**、没有逐局正确率序列 → 算不出斜率，也算不出「首错音素再遇改善率」。
2. `EP02.played` 只存累计完赛数，没有「主动重玩」「会话时长」「中途放弃」→ 算不出意愿类指标。
3. `window.__rally` 全是**单局内存态**，下一局 `beginCountdown()` 会 `race.dispose()` 冲掉 → `rockHits / cheerSeq / gates[]` 无法跨局聚合。
4. 结论：必须补**一处极小的跨局落盘**（§2），其余指标全部由现有 getter 零成本取得。

## 1. 指标字典（12 项 · 4 类各 3 项）

### 1.1 动机类 —— 「孩子自己还想再来吗」（3 项）

| 编号 | 指标 | 精确定义 | 采集点 | 计算口径 | 健康阈值（建议·需标定） |
|---|---|---|---|---|---|
| A1 | **主动重玩率 VRR** | 完赛后**孩子自主**点击「再跑一场」的局数占完赛局数的比例。自动口径与「校正口径」并存，门控只用校正口径 | N6 `again` / N8 `games`（自动）；P 表 B/C（校正） | 自动 `= fwd.again / fwd.games`；**校正** `= Σ(自愿 againClick) / 有效局数`，剔除「主试提示>0 / 代操作 / 埋点异常」局（§3.4 / §3.6） | ≥ **0.50**，且两组各自 ≥ **0.35**；自动值仅作交叉校验，不得单独入 PASS |
| A2 | **首局续玩率** | 完成第 1 局后，在**同一会话内**自主再开一局的会话占比 | N2 `sess` + N9 `ring[0]` / `ring[11]` | 按 `ring[].sess` 分组，取每组首局；`= 首局 againFlag=1 的会话数 / 有 ≥1 局的会话数` | ≥ **0.40** |
| A3 | **主动放弃率** | 开局后未完赛即回标题 / 退出 / 关页的局数占开局局数的比例 | N5 `starts` + N7 `quits` | `= fwd.quits / fwd.starts`（`pagehide` 兜底未显式点按钮的离开） | ≤ **0.20**；> 0.30 直接 FAIL |

> **口径纪律**：A1 的自动值不区分「想玩 / 被要求玩」，这正是 §4 FP-3 的假阳性来源；门控必须使用 §3 的校正值。

### 1.2 投入类 —— 「是否真的沉进去」（3 项）

| 编号 | 指标 | 精确定义 | 采集点 | 计算口径 | 健康阈值（建议·需标定） |
|---|---|---|---|---|---|
| B1 | **单会话自愿时长** | 从会话开始到**最后一次主动输入**的墙钟时长；不含 quiz / paused / results / 榜 / 店冻结段；≥60s 无输入空闲段由主试在表 A 手工扣除 | N3 `start` + N4 `last`；P 表 A | `= fwd.last − fwd.start`（epoch ms → s）；按组取**中位数**，不取均值 | 小学生 ≥ **300s**、初中生 ≥ **240s**；且任一组中位数不得 < 1 局（≈200s） |
| B2 | **主动重听率** | 孩子主动点「再听一次」/ 按 E 的闸门数占已播放闸门数的比例。反映「在认真听但没听清」，过低=乱选 / 没在听，过高=音频或难度有问题 | E3 `gates[].replayed / played`；N9 `ring[6]` | `= Σ gates.filter(g=>g.replayed).length / Σ gates.filter(g=>g.played).length`（每局，跨局取均值） | 健康带宽 **0.10 – 0.45**；< 0.05 或 > 0.60 触发复核 |
| B3 | **单位时间有效听辨数 EDPM** | 每在赛分钟**已判定**的闸门数（排除 `unheard` 未听门，排除冻结时长） | E3 `gates[].judged` + E4 `result().time`；N9 `ring[4]/ring[5]` | `= judged / (time / 60)`；`judged = total − unheard.length = gates.filter(g=>g.judged).length`；`time` 为 `state.finishTime`（F-3 冻结不计） | **1.2 – 2.5** 道/分钟；4 道 / ≤3 分钟 ≈ 1.33 为自然下限；< 1.2 说明门被跳过 / 没听完 |

### 1.3 学习成效类 —— 「是否真的学会」（3 项）

| 编号 | 指标 | 精确定义 | 采集点 | 计算口径 | 健康阈值（建议·需标定） |
|---|---|---|---|---|---|
| C1 | **单局闸门听对率** | 分岔门命中数 / 门数；额外惩罚题**不参与**（与 `race.result()` / `scoreRace()` 口径一致） | E4 `correct / total`；N9 `ring[2]`；E1 `bestAcc` 交叉校验 | `= correct / total`（每局，total=4，整数百分比 `acc100`） | 第 1 局 ≥ **0.40**、第 4 局 ≥ **0.60**；连续 3 局 ≥ 0.95 触发**天花板复核**（FP-2） |
| C2 | **正确率随局数斜率** | 同一孩子 / 同一浏览器配置下，逐局听对率的最小二乘斜率 | N9 `ring[1]`（局序）+ `ring[2]`（acc100） | 对最近 ≥4 局做最小二乘，`slope` 单位 = 百分点/局；样本 <4 局记 `INSUFFICIENT`，**不得记 0** | ≥ **+5** 百分点/局；显著 < 0（越玩越差）→ FAIL |
| C3 | **首错音素再遇改善率** | 同一 `pairKey` / `spoken.unit` 首次判错、之后任一局再遇判对的词对占比（迁移 / 保持信号） | E3 `gates[].{pairKey, spoken.unit, hit}` 只读快照，主试逐局抄入 P 表 B；**不新增字段、不落盘** | `= (首次错 且 再遇≥1次 且 再遇判对 的词对数) / (首次错 且 再遇≥1次 的词对数)` | ≥ **0.30**；有效再遇样本 <2 记 `INSUFFICIENT` |

> **反冒充纪律**：C1 单独高不等于「学会」。C1 必须与 B2、B3、C3 **三件套**同时成立才计学习成效（§4 FP-2）。

### 1.4 竞赛感类 —— 「三辆车与石头是否成立」（3 项）

| 编号 | 指标 | 精确定义 | 采集点 | 计算口径 | 健康阈值（建议·需标定） |
|---|---|---|---|---|---|
| D1 | **危机应对率（躲石成功率）** | 成功规避的石头数占本局石头总数；等价交叉校验 `1 − rockHits / rockBudget` | E2 `pickups` / `rockHits` / `rockBudget`；E3 `pickups[].cleared` | `= pickups.filter(p=>p.kind==="rock" && p.cleared).length / pickups.filter(p=>p.kind==="rock").length` | **0.30 – 0.90**；< 0.30 = 危机变惩罚，> 0.90 = 没有危机感 |
| D2 | **败局续玩率比** | 输了（第 3 名）之后仍自主再跑的比例，相对没输之后的比例 | N9 `ring[3]`（place）+ `ring[11]`（againFlag） | `= (place=3 局中 againFlag=1 占比) / (place∈{1,2} 局中 againFlag=1 占比)`；分母为 0 记 `INSUFFICIENT` | ≥ **0.60**（输了不劝退，说明竞赛驱动成立） |
| D3 | **正反馈密度** | 每完赛局触发的欢呼 / 局部彩带次数（闸门命中 + 成功躲石两源） | E2 `cheerSeq`；N9 `ring[10]` | `= cheerSeq / 完赛局数` | ≥ **2.0** 次/局；`= 0` 视为机制从未触发，直接触发假阳性复核 |

### 2.5 ⚠️ 跨站保真风险（需用户拍板，见 §6 D-1）

姊妹站 `音标大闯关/js/store.js` 的 `RALLY_FOREIGN` 白名单（11 键，F-10）**不含 `fwd`**。`save()` 会 `refreshFromRaw(data, rawRead())` 后 `writeRaw(data)` **全量写回**；若大闯关标签在拉力赛写入 `fwd` 之前已加载，之后任一时刻 `save()`，其内存视图不含 `fwd` → **静默抹掉埋点**。拉力赛侧 `commit()` 是「写前重读最新整对象」，自身不会抹；风险只来自姊妹站的陈旧内存视图。

三个可选处置（**本轮只出规格，不改任何产品代码**）：

| 选项 | 做法 | 代价 |
|---|---|---|
| **(a) 推荐** | 姊妹站 `RALLY_FOREIGN` 追加 `"fwd"`（1 行）；保持单键 | 触碰姊妹站 1 行，须用户批准 |
| (b) | 改用独立键 `ipa-quest-v1-fwd`（拉力赛独占，姊妹站零改动） | 破坏「两站单键」现状 |
| (c) | 只存内存 `window.__rally.fwd`、Playtest 现场导出 | 失去跨局 / 跨会话斜率与重玩率，A1/A2/C2 不可算 |

## 3. 一轮轻 Playtest 方案

### 3.1 样本 / 分组 / 会话规则

- **小学生组（6–12）≥6 人、初中生组（12–15）≥6 人**；任一组 <5 人 → 只出「标定报告」，不出 PASS / FAIL。
- 每人 1 个会话；**每组一个独立浏览器配置文件 / 无痕窗口**（隔离 localStorage，防 `EP02.played` 与 `ring` 串组）。
- 会话上限：**25 分钟或最多 4 局，先到者止**；到点主试中性收尾「今天先到这里」，**不说服、不挽留**。
- **中性开场白（统一逐字）**：「你自己试试，想停就停，想继续也可以继续。」之后主试**全程不发指令、不提示、不鼓励、不提问、不代操作**。
- 不告知「要玩几局」；结果页出现后**不提示**「再跑一场」按钮的存在。

### 3.2 单局观察项（勾选 / 计数）

1. 是否**自主**点击「上赛道」（`startInitiator`：孩子 / 主试）
2. 4 道闸门各有无明确转向（0–4）
3. 「再听一次」次数（0–4，与 `gates[].replayed` 交叉校验）
4. 石头前是否主动按空格 / 点跳（0–2）
5. 结果页停留秒数；`t_again` = 结果页可见 → 点「再跑一场」的秒数
6. 名次（1 / 2 / 3）、是否复看名次或错词列表
7. 是否中途回标题 / 暂停退出
8. **主试提示次数（必须为 0）**；>0 该局标「被要求」

### 3.3 问卷（5 题，匿名勾选，约 1 分钟）

| 题 | 题干 | 选项 |
|---|---|---|
| Q1 | 还想再玩一局吗？ | ☐想　☐不想　☐随便 |
| Q2 | 刚才最好玩的是？（单选） | ☐①画面和车　☐②听音选车道　☐③跟两辆车比名次　☐④躲石头　☐⑤说不清 |
| Q3 | 有没有哪次没听清、想再听一遍？ | ☐0 次　☐1 次　☐2 次及以上 |
| Q4 | 如果明天还能玩，你会自己打开吗？ | ☐会　☐不会　☐看情况 |
| Q5 | 有没有哪一段觉得太难、想关掉？ | ☐没有　☐有（第 ____ 局） |

> 不写姓名、不写具体年龄、不写学校；只勾「小学生组 / 初中生组」。问卷结果**不进 localStorage**。

### 3.4 「再来一局」行为观测（可量化）

- 结果页出现后开 **90 秒静默观察窗**，主试不说话。
- `againClick = 1` **当且仅当**：无任何提示 ∧ 孩子自己点 ∧ `t_again ≤ 30s`；`30s < t_again ≤ 90s` 记「犹豫」；`>90s` 或点「回标题」记 0。
- 会话末抄 `fwd.again` 与 `ring[last][11]`，与人工 `againClick` **逐局对账**；不一致 → 该样本标「埋点异常」，计入 FP-3。
- **校正主动重玩率** `= Σ(自愿 againClick) / 有效局数`，剔除「主试提示>0」「代操作」「埋点异常」局。**门控只用校正值**；自动 `fwd.again / fwd.games` 仅作交叉校验。

### 3.5 区分「喜欢画面」与「喜欢竞速」

| 证据 | 画面偏好 | 竞速偏好 |
|---|---|---|
| Q2 | 选 ① | 选 ③ / ④ |
| 名次行为 | 不关心 | 结果页复看名次、NPC 贴近时加速 / 变线、主动再跑争名次 |
| 躲石 / 输入 | 跳石 0–1 次，非闸门段几乎无转向 | 跳石 ≥1 次，非闸门段仍持续转向 |
| 商店 / 车身 | 主动换颜色 / 装饰 | 不主动 |
| 30s 静止预观察（可选） | 注视车与场景时间长，开赛后输入密度低 | 开赛后输入密度明显高于静止段 |

**判定线**：
- Q2 选 ① ∧ 名次/躲石行为合计 ≤1 → **画面偏好**；
- 名次/躲石行为 ≥2 ∧ Q2 选 ③/④ → **竞速偏好**；
- 两者皆低 → **核心循环无吸引**，直接触发 §5 FAIL 信号。
- 两类偏好**分别计数**，不得合并成「喜欢」。补充假阳性：视觉断言全绿 + Q2 选① 高分 + `againClick=0` → 喜欢的是静态画面而非核心循环，单列不计入「愿意玩」。

### 3.6 区分「想玩」与「被要求玩」

硬约束 + 五信号：

| # | 信号 | 采集 |
|---|---|---|
| 1 | **主试提示次数 = 0**（硬性） | 表 A / 表 B；>0 即作废该局自愿性 |
| 2 | `startInitiator = 孩子`（自己按「上赛道」） | 表 B |
| 3 | 结果页 ≤30s **自主**点「再跑一场」 | 表 B `t_again` |
| 4 | Q1 = 想 / Q4 = 会 | 表 C（**佐证，不能单独替代行为**） |
| 5 | 陪坐人「有 / 无」 | 表 A（只勾有无，不记身份） |

**判定**：`1 ∧ 2 ∧ 3` 同时成立才计入 VRR 分子。
- `1 ∧ 2` 成立但 `3` 不成立 → 记「想玩但未续玩」，单独列，**不并入 PASS**；
- `1` 不成立 → 记「被要求」，单独列，**不得计入任何 PASS 判据**；
- Q1/Q4 仅作佐证，问卷高分 + 行为为 0 不判「想玩」（防社会赞许偏差）。

## 4. 假阳性检测（工程全绿但其实没人想玩）

| 编号 | 检测 | 触发条件 | 为什么是假阳性 | 处置 |
|---|---|---|---|---|
| **FP-1** | **全绿零重玩** | 121 项门控 + 18 项交互断言 + headless 11 场 ≤180s + WebGL 四项错误归零 **全部 PASS**，但 `fwd.games ≥ 6` 且 `fwd.again = 0`（或校正 VRR = 0） | 门控只证明「功能没坏」，不证明「有人想再玩」。零重玩是产品失败的最强信号，却与所有工程判据完全兼容 | 直接判 **FAIL**；**不得引用任何工程绿项抵消**；产品门控独立出报告（§5.1） |
| **FP-2** | **高正确率零投入 / 天花板** | `EP02.bestAcc ≥ 0.95` 连续 3 局，同时 `ring[].replays = 0`、`ring[].judged = 4`、会话时长 < 1 局、`cheerSeq = 0` | 可能是题面泄答案、代玩、脚本自动步进，或题库过易；把「工程判定正确」误当「孩子学会了」 | 正确率必须与 **B2 + B3 + C3 三件套**同时成立才计学习成效；单看 acc 不判 PASS；触发人工复核（回看表 B 转向 / 跳石记录 + 表 A 陪坐人） |
| **FP-3** | **被要求玩的假重玩** | `fwd.again / fwd.games ≥ 0.6`，但表 B/C「主试提示 >0」或「`againClick` 与 `fwd.again` 不一致」的局占比 ≥ 50% | 自动埋点只记「点了按钮」，记不了「谁让他点的」；家长 / 主试在场时重玩率系统性虚高 | 门控只用 §3.4 **校正主动重玩率**；自动值仅作交叉校验；不一致样本标「埋点异常」且**不计入分子** |

**补充（并入 §3.5，不单列判据）**：**画面偏好冒充产品成功** —— 视觉断言全绿 + Q2 选① 高分，但名次 / 躲石行为 ≤1、`againClick = 0` → 喜欢的是静态画面而非核心循环，按「画面偏好」单列，不计入「愿意玩」。

**根因一句话**：工程门控的断言对象是「代码状态」，产品门控的断言对象是「人的行为」；两者没有逻辑蕴含关系，任何方向的替代都是假阳性。

## 5. 门控口径（针对「愿意玩」，非工程正确性）

### 5.1 两套门控的边界（独立、互不替代）

| | 工程门控（既有） | 产品门控（本文） |
|---|---|---|
| 判什么 | 代码 / 判定 / 渲染 / 资产正确性 | 孩子是否愿意玩、是否真的学会 |
| 证据 | 121 项门控、18 项交互断言、headless 11 场 ≤180s、WebGL 四项错误归零 | §1 的 12 项指标、§3 的 Playtest 记录表、§4 的 FP-1/2/3 |
| 触发时机 | 每次代码改动 | 每次玩法 / 视觉 / 题库优化后一轮轻 Playtest |
| 关系 | **前置**：工程门控 FAIL 时不启动产品门控（不浪费孩子时间） | **独立**：工程门控 PASS **不是**产品门控的充分条件；产品门控 PASS 也不能替代工程回归 |
| 签字 | 工程侧 | **用户（人工）最终放行**；本报告只给判定建议（advisory） |

**互不替代三条**：
1. 工程全绿 ∧ 产品 FAIL → **不得**以「功能没坏」放行（FP-1）。
2. 产品全绿 ∧ 工程 FAIL → **不得**以「孩子喜欢」跳过回归。
3. 两套各自出报告、各自列阻塞项、各自签字；任何一套的 NOTE / CONCERNS **不得被另一套的 PASS 冲抵**。

### 5.2 PASS / CONCERNS / FAIL 判定口径

#### PASS（以下**全部同时**满足）

| 编号 | 条件 |
|---|---|
| P0 | 前置：工程门控全绿；**FP-1 / FP-2 / FP-3 三项全阴性** |
| P1 | 样本：每组 ≥5 人、每组 ≥10 局，且 12 项阈值已完成**实测标定**（**首轮不判 PASS**） |
| P2 | 动机：校正 VRR ≥ 阈值、A2 首局续玩率 ≥ 阈值、A3 主动放弃率 ≤ 阈值 |
| P3 | 投入：两组会话时长中位数**各自** ≥ 阈值；B2 落在 0.10–0.45；B3 落在 1.2–2.5 |
| P4 | 学习：C2 斜率 ≥ 阈值（或「不显著为负」且 C3 ≥ 阈值）；**两组分别达标** |
| P5 | 竞赛：D1 落在 [下限, 上限]、D2 ≥ 阈值、D3 > 0 |
| P6 | 分层：小学生组与初中生组**各自**满足 P2–P5；不得用合并均值掩盖任一组 |
| P7 | 证据：12 项指标无 `MISSING`；`ring` 采集链路与表 B / 表 D 对账一致 |

#### CONCERNS（任一即判，且**必须列出整改项 + 下一轮复测点**）

- 阈值尚未标定 → **首轮 Playtest 的默认结论**；
- 样本量不足（任一指标 `INSUFFICIENT`）但已观测数据无负面信号；
- 单项落在阈值 ±10% 灰区；
- 两组中一组达标、另一组仅灰区（**不合并**）；
- FP 检测 **1 项**阳性但可解释且已列整改项；
- 埋点链路部分异常（表 D 与表 B 个别不一致）但不影响主结论。

> CONCERNS **不得静默放行**；必须显式列出整改项与复测点。

#### FAIL（任一即 FAIL）

- 校正 VRR = 0 且 `games ≥ 6`（**FP-1 阳性**）；
- A3 主动放弃率 > 阈值上限的 1.5 倍，或**任一组**会话时长中位数 < 1 局（≈200s）；
- C2 斜率显著为负（越玩越差），或**任一组**「核心循环无吸引」人数 ≥ 半数；
- **FP 检测 ≥2 项阳性**；
- 12 项指标中任一为 `MISSING`（采集链路不可用）→ 数据不可采即不可判，按 FAIL 处理并**先修埋点**；
- 工程门控 FAIL（前置不满足）→ 产品门控本次不判，整体 FAIL。

### 5.3 判定输出格式

```
PRODUCT GATE: PASS / CONCERNS / FAIL
· 小学生组 n=__ 人 / __ 局；初中生组 n=__ 人 / __ 局
· 12 指标逐项：[达标 / 灰区 / 未达标 / INSUFFICIENT / MISSING]（两组分列）
· FP-1 / FP-2 / FP-3：阴 / 阳（逐项）
· 阻塞项：____   整改项：____   需用户拍板项：____
· 工程门控状态：____（仅作前置，不参与本判定）
```

> 质量门为**建议性门控（advisory）**；最终放行由用户决定，高影响动作（发布签字）须人工审批。

#### C-9 · `rockSeen` 的「0–2」不成立，实际 0–4（新发现，阻断 D1）

**代码事实**：`js/race.js:145` `rockBases = [0.4, 0.82]`、`item.t ∈ [0,1)`；`:648` `odo = floor(player.odo / L) * L + item.t * L`；`:691-695` 跨圈复位 `taken / armed / cleared`。→ **2 颗石头 × 2 圈 = 最多 4 次 settle 定案**。`rockHits` 受 `rockBudget = 2` 封顶（`:628`），但 `rockSeen` 在 settle 处无条件 `+1`，不受封顶影响。
