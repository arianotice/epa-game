## §1 坐标系与尺度换算（工程落地第一块，先看这节）

> 这是把 2D 判定域接到 3D 世界层的关键，也是最容易出错的地方。**判定域用 `track.js` 的「单位」，渲染域用「米」，两者靠一个显式 `WORLD_SCALE` 关联，绝不混算、绝不写回。**

### 1.1 2D 坐标系事实（逐字核对 `js/track.js`）

```js
/* 俯视椭圆赛道。世界坐标 y 向下，与画布一致。1 单位约等于画面上的 1 像素量级。 */
export function createTrack(tuning) { /* straight:6800, radius:900, roadHalf:520 */ }
function sample(t) {        // t ∈ [0,1) 沿环归一化
  return { x: p.x, y: p.y, fx, fy, rx: -fy, ry: fx, t: tt };  // (fx,fy) 归一化前切向, (rx,ry) 右法向
}
export function offsetPoint(s, lateral) { return { x: s.x + s.rx * lateral, y: s.y + s.ry * lateral }; }
// return { length: total, sample, samples, roadHalf: tuning.roadHalf };  samples 预采样 N=520
```

- 关键参数（`js/config.js TUNING`）：`straight=6800` / `radius=900` / `roadHalf=520` / `laneLateral=0.55` / `laps=2` / `commits=[0.24,0.68]`。
- `sample(t)` 给出：中心点 `(x,y)`（俯视平面）、**前切向** `(fx,fy)`、**右法向** `(rx,ry)=(-fy,fx)`、沿环归一化 `t`。
- 车辆横向 `lateral ∈ [-1,1]`（2D `render.js` clamp 后用 `vis*roadHalf` 换算为像素偏移；车道中心 `lateral=±laneLateral=±0.55`）。
- `main.js` 的 2D 跟随相机 `camera={x,y,h}`，`followCamera()` 用 `s.fx*90 + s.rx*vis*roadHalf` 定位、`atan2(s.fy,s.fx)` 定朝向，**这套 2D 相机逻辑 P1 不动**，3D 相机另起（§2），二者只共享「车在 `sample(t)`」这一事实。

### 1.2 3D 轴映射约定（【建议值】，但一旦选定须全场一致）

把 2D 俯视 `(x, y)` 平面映射到 three 的**水平 `(X, Z)` 平面**，`Y` 为高度（向上为正）：

```
X =  s.x * WORLD_SCALE
Z =  s.y * WORLD_SCALE          // 2D y 向下 → three +Z
Y =  0                          // 路面基准，向上为正
forward3 = normalize( s.fx, 0,  s.fy )     // 车头 / 赛道前进方向
right3   = normalize( s.rx, 0,  s.ry )     // 横向右 = (-fy, 0, fx)
up3      = (0, 1, 0)
```

- **车体局部坐标约定**（§3 所有几何表用此）：车头朝 **+Z**、车宽沿 **X**、高度 **Y**、车尾朝 -Z（相机在车后看 +Z，符合「车尾 3/4 视角、看到后脑与肩线」）。车体 group 的朝向由 `forward3` 用 `quaternion.setFromUnitVectors((0,0,1), forward3)` 或 `lookAt` 每帧设定。
- **防镜像校验**：2D 是 y 向下的左手观感，3D 是右手系。若实机出现「左右车道镜像 / 车头朝向反」，优先翻转 `forward3`/`right3` 的 **Z 分量**或改用 `Z = -s.y*WORLD_SCALE`，**不要改判定域的 `lateral` 符号**。这是纯渲染层修正。
- **横向换算**：3D 中车辆中心 = `center(t) + right3 * (lateral * roadHalf * WORLD_SCALE)`；车道分隔线 = `center(t) ± right3 * (0 * ...)` 的中线（§4.2）。

### 1.3 `WORLD_SCALE` 与关键长度换算表（【建议值】）

定义 `WORLD_SCALE = 0.008 m / unit`（即 **1 m = 125 unit**）。选它的理由：让「半路宽 `roadHalf=520`」≈ 4.16 m（双车道总宽 8.32 m，符合卡丁车道感），且「车长 1.6 m」正好 = 200 unit、`lateral=±1` 落在路缘内，与 2D 观感自洽。

| 量 | 2D（unit） | ×0.008 → 3D（m） | 用途 |
|---|---|---|---|
| `roadHalf` 半路宽 | 520 | **4.16** | 路面带半宽、两车道可读校验 |
| 整路宽 `2×roadHalf` | 1040 | 8.32 | 路面 ribbon 全宽 |
| 车道中心 `±0.55×roadHalf` | ±286 | ±2.29 | 左右车道中心（听音选车道） |
| 车长（v1.1 §C.0） | 200 | **1.60** | 车体基准 |
| 车宽 / 车高 | 125 / 106 | 1.00 / 0.85 | 长:宽:高 = 1.6:1.0:0.85 |
| 直道 `straight` | 6800 | 54.4 | 直道段长度 |
| 弯道半径 `radius` | 900 | 7.2 | 椭圆两端半圆 |
| 整圈 `length` ≈ 19256 | — | ≈154 | 两圈 ≈308 m |
| 跟车距离（v1.1 §B） | 1000 | 8.0 | 相机与车尾间距 |
| 机位高（§B） | 450 | 3.6 | 相机离地 |
| 路牌预告距离 15–45 m | — | 15–45 | 中层，纸雾开始收敛 |
| 纸雾远层起点 45 m | 5625 | 45 | v1.1 §B.2 三层分界 |

> **诚实标注**：`WORLD_SCALE` 是美术侧为让米制参数落地给的**可调工程参数**。若工程侧沿用「3D 世界直接用 unit 域、相机也用 unit」更省事，可令 `WORLD_SCALE=1` 并把 §2/§3 所有「米」×125 换成 unit——**但 §2.3 的两车道可见校验、§5 的抖动 ≤3px@375 仍须按屏幕像素单独复核**。无论选哪套，判定域 `odo/lateral` 数值不变。**2D 里程/速度（如 `speed 300`）是单位/秒，3D 速度感靠镜头/FOV/粒子表现，不需要、也不应该反推成真实物理速度**。

### 2.2 FOV 换算公式与竖屏 vFov 陷阱（【建议值】+ 重要提示）

three `PerspectiveCamera.fov` 是**垂直** FOV。v1.1 §B 的「锁水平 FOV 60–66°」是**横屏/设计口径**；竖屏 `aspect<1` 时直接锁水平会导致垂直 FOV 爆炸、边缘拉伸：

```
vFov = 2·atan( tan(hFov/2) / aspect )
hFov = 2·atan( tan(vFov/2) · aspect )
```

| 视口 | aspect | 若 hFov=62° → vFov | 后果 |
|---|---|---|---|
| 375×780 | 0.481 | **≈ 103°** | 畸变明显，边缘纸雾/护栏拉伸，low-poly 立体书虽较耐受但不推荐 |
| 320×568 | 0.563 | ≈ 94° | 仍偏大 |
| PC 16:9 | 1.778 | ≈ 37° | 正常 |

**美术侧裁决（【建议值】，须工程实机确认）**：竖屏**改以垂直 FOV 为锚**，取 `camera.fov = 74°–80°`（375）/ `70°–76°`（320×568），水平 FOV 由 aspect 自然得到：

| 视口 | aspect | 取 vFov | 反算 hFov | 跟车 8m 处可见路宽 `2·8·tan(hFov/2)` | 是否覆盖 8.32m 双车道 |
|---|---|---|---|---|---|
| 375×780 | 0.481 | 78° | ≈ 42.4° | ≈ 6.2 m | ⚠️ 略不足 → 见下方补偿 |
| 320×568 | 0.563 | 74° | ≈ 45.9° | ≈ 6.8 m | ⚠️ 略不足 |

**补偿（三选一或组合，均属【建议值】）**：① 竖屏跟车距离拉到 **8.5 m**（可见宽 ↑约 6%）；② 高机位 + 18–20° 俯角让**透视投影**把更远路面压进画面（可见宽按地面交线算，实际比水平截线大）；③ hFov 下限保 48°（vFov 相应到 ~86°，畸变换可读）。**验收口径以「两条车道中心 `lateral=±0.55` 与前方路牌同时清晰入画」为准，而非死守某个 FOV 数字**——这正是「玩家必须同时看见两车道与路牌」的玩法硬约束。PC 横屏维持 v1.1 的锁水平 60–66°（vFov≈37°）不变。

### 2.3 构图安全区与两车道可见校验（硬约束）

- **竖屏安全区**（沿用 v1.1 §E.5）：上 `env(safe-area-inset-top)+8px`、下 `env(safe-area-inset-bottom)+#touch 高度(≈100px)`、左右各 12px。3D 相机取景须为这些 HUD/触控带留足**不被关键 3D 信息占用**的余量；玩家车与两车道落在**下 58–62%** 的路面区，消失点/地标/路牌在**上 38–42%**。
- **消失点**：通过 look-at 点高度与俯角共同决定，实机校准到「画面顶部起 40% ±2%」。
- **两车道可读校验表**（每帧/首帧各验一次，建议 quality-lead 做静态断言）：`center(t)` 前方 8–25 m 区间内，`lateral=−0.55` 与 `+0.55` 两条车道中心、以及分叉前 15–45 m 的世界空间路牌（§4.4）**必须同时落在视锥内且不被车身/护栏遮挡**。
- **看不到全景**：`far=120` + `FogExp2` 把 45 m 外收敛为纸色（§4.7），玩家在任何帧都看不到整条闭环赛道；方位感靠右上角该轮小地图（2D DOM）、路牌、恒地标、圈数进度（v1.1 §B.3），**不靠 3D 全景**。

### 2.4 跟随 / 侧倾 / 抖动 / 速度感实现要点（【建议值】）

- **临界阻尼弹簧**（非线性 lerp 即可，无需物理引擎）：`k = 1 - exp(-dt / τ)`，`τ=0.22s`（位置）、`0.30s`（偏航）；`snap=true`（模式切换 / 重置）时 `k=1` 立即对齐。这与 2D `followCamera()` 的 `k=min(1,dt*8)` 观感一致但更稳。
- **相机位置**：`camPos = playerPos - forward3*distance + up3*height - right3*(转弯侧倾补偿)`；`camLookAt = playerPos + forward3*lookAhead`。侧倾只给镜头 `roll ±2–4°`（0.15s lerp）+ 车身自身 `roll ±5–7°`，**世界绝不倾斜**（防晕）。
- **抖动**：仅 `boost/turbo/碰撞` 触发，白噪声经低通（截止 ≤30Hz），峰值 ≤3px@375 / ≤0.4°，`reduced=true` 时乘 0。
- **FOV 呼吸**：boost 时 `fov += 4–6°`（0.2s ease-in/out），结束回基准；禁止全屏径向模糊 / 景深 / bloom（方案甲 + 防晕）。
- **速度感**只给 L0–L1 世界层（护栏 `InstancedMesh` 滚动、boost 尾焰、边缘纸纤维流线、远层视差、轮毂转速），**屏幕 HUD 绝对静止**（不随 shake/roll/FOV）。

### 2.5 320×568 / 375×780 兼容（硬约束）

- 最小适配 **320×568**（`quality-lead #31` 门控基线）。两档共用同一套相机逻辑，只按 aspect 重算 §2.2 的 vFov 与 §2.4 的 lookAhead；不得为小屏**删减**两车道、路牌、小地图、圈数、进度条、combo、quiz 卡片可读性，不得缩小触控热区与字号（v1.1 §H.3 硬底线）。
- `dpr={[1,2]}` 沿用 probe；`320×568` 低配建议直接进 L1 档（DPR≤1.5、关动态阴影、粒子减半），**帧率优先于特效**（平顺本身防晕）。

### 2.6 `reduced` / 动敏降级（硬约束）

复用 `render.js` 已有 `reduced` 分支（其 `shake` 已置零）：`reduced=true` 时抖动/侧倾/FOV 呼吸/速度线/边缘流线**全部归零**，速度感改由 HUD 数字 + 静态尾焰 + 路牌后移表达，镜头保持完全静止可预期。默认跟随 `prefers-reduced-motion`。

## §4 赛道 · 由 `track.sample(t)` 生成 3D 路面带（硬约束）

> **核心原则**：判定域 `track.sample(t)` 提供「形状 / 切向 / 沿环 t / 门位」；3D 渲染层只把它**可视化**，绝不写回。四区是四场独立杯赛（`RACE_MAPS` 的 `camp/castle/kingdom/peak`），共用同一套生成逻辑，靠**材质换色 + 换道具预设**切换，零第二套几何。

### 4.1 3D 路面带 ribbon 生成法（【建议值】可直接实现）

用 `createTrack().samples`（已预采样 `N=520`）或按需 `sample(i/N)` 构造一条 `BufferGeometry` 三角带：

```
for i in 0..N:
  s = sample(i/N)
  c = ( s.x*WORLD_SCALE, 0, s.y*WORLD_SCALE )        // 中心（§1.2）
  r = normalize( s.rx, 0, s.ry )                      // 右法向
  L = c - r * ( roadHalf*WORLD_SCALE )                // 左路缘 ≈4.16m
  R = c + r * ( roadHalf*WORLD_SCALE )                // 右路缘
  emit vertices L, R with uv(0/1, i/N)                // 供 §4.2/§4.6 纹理或渐变
connect consecutive quads → 2 triangles; 闭合回 i=0（闭环）
material: MeshStandardMaterial( zone 主色, roughness 见 §4.3, metalness 0, side=DoubleSide )
```

- **纵向分段**：`N=520` 直用即可（与 2D `samples` 同源，保证门位/圈数视觉对齐）；可在近层 0–12m 加密、远层抽稀以省三角（§4.7 细节衰减）。
- **闭合**：椭圆两端由 `sample` 天然闭环，`t` 绕回 0 时接缝对齐。

### 4.2 车道分隔 / 暗红虚线路径 / 宝石车道标记

| 元素 | 几何 | 材质 | 规则 |
|---|---|---|---|
| **中央车道分隔** | 沿 `center(t)` 的虚线带（短 box / dashed line，`InstancedMesh`） | 奶白 `#f6ead0` 或区路缘色 / .9 / 0 | 只区分左右车道，**不靠红绿**；虚线周期随距淡出 |
| **暗红虚线探险路径** | 贴地细带（decal 或略高于路面 0.005m 的 ribbon） | `#8C4034` / .95 / 0 | 贯穿近/中/远三层，是「我在往哪开」的第一视觉锚（v1.1 §B.2）；分叉前开始分开（L2 环境指示，不含左右正确性） |
| **宝石车道标记** | 地面菱形薄片 | 三宝石语义色（`#B03A2E`/`#2E5F8A`/`#2E7D5B`）/ .4 / 0.6 + 轻微 emissive | 只承载**教学语义与关键交互**，S 55–75%、屏幕占比 ≤8%；**必须叠加形状冗余**（§7）；判定完成前**不得**用 `is-long`/`is-short` 语义色标注哪侧正确（C3 / v2 M5） |

### 4.4 路牌几何（分叉靠前方预告，硬约束）

- **形制**：世界空间 billboard = 立柱（Cylinder/Box）+ 牌板（Box，圆角更佳）+ **空白牌面容器**。四区共用同一形制、只换材质与宝石色。
- **位置**：分叉前 **15–45 m** 沿 `forward3`（`commitT` 门位只取其**位置**，不取内容，C3）。
- **屏幕空间最小尺寸锁**（v1.1 §E.1 L2）：牌面不随距离无限缩小，设 `minScreenPx`（建议竖屏牌宽 ≥96px、牌面 IPA 位 ≥26px 见 §7），保证 375px 可读。
- **牌面文字**：**空白容器**，分叉两项 + 方向箭头由 DOM 合成（C4）；**不得出现 `is-long`/`is-short` 语义色或正确侧高亮**（C3）。
- **材质**：木/石立柱哑光、牌板奶白 `#f6ead0` 不透明、内层米金线 `#b99b6b` + 外层墨蓝 `rgba(35,54,78,.35)` 双层描边（抗运动背景，v1.1 §E.2）；烫金小罗盘角标每牌 ≤1 处。

### 4.5 起终点门 / 区门（v1.1 §D.2）

- **形制**：两立柱 + 横梁 + 空白牌位（拱门 / 界碑），**四区共用同一几何**、换材质与宝石色。
- **位置**：起终点各一，沿 `t=0` 与圈数进度对应；门位与 `TUNING.commits=[0.24,0.68]` × `laps=2` 的 4 个判定位**视觉对齐但内容解耦**——闸门几何只读取 `commitT` 的**位置**（C3），不读 `spoken/correctLateral`。
- **最小对立对镜像闸门（v2 M8，P1 可选不做）**：左右两片几何镜像、只差一个「差异部件」（≥24px、置于闸门上半部不被车遮挡、两侧信息量相等），差异由参数 diff 驱动、**不高亮哪侧是答案**。列为可选升级（§9）。

### 4.6 护栏 / 道具阵列（【建议值】）

- 沿 `center(t) ± right3*(roadHalf*WORLD_SCALE + 0.3)` 用 `InstancedMesh` 铺护栏（木桩麻绳 / 城垛 / 灯柱 / 石墩，四区换 preset）、灯柱、界碑、宝石格。
- **每区 ≤4 个可复用道具模块**（v1.1 §0.3），靠材质换色 + 镜像 + 缩放生成四区差异；禁用逐物体独立材质以控 draw call。
- **恒地标**（v1.1 §B.3）：每区 1 个始终可见的天际线地标（camp 篝火旗杆+宝箱 / castle 元音圆厅穹顶 / kingdom 清浊双塔 / peak 峰顶终点星标），置于远层作「北极星」。P1 起步可用**简化剪影几何**（塔=叠 Cylinder+Box，星标=Octahedron），零外部模型。

### 4.7 纸雾 / 三层远景 / 细节随距衰减（硬约束：方案甲签名效果）

- **雾**：沿用 P0 探针 `fogExp2 ["#efe6d3", 0.045]` 作中性默认；四区可把 `FogColor` 插值到本区天光色（§4.3），最终**收敛到羊皮纸色 `#E9D8B4` / `#e7d3a8`**——赛道不是消失在雾里，是「消失回纸里」。`far=120` 覆盖收敛。
- **三层**（v1.1 §B.2 / v2 §1.2⑥）：
  - 近层 **0–12 m**：密度 100%、全对比全饱和、完整烫金与墨线细节；
  - 中层 **12–45 m**：密度 ≤40%、饱和 −10~15%、对比 −10%、混入天光色，路牌在此层出现并锁屏幕最小尺寸；
  - 远层 **>45 m**：密度 ≤10%（剪影化），只留地标剪影 + 天空穹顶，收敛到纸色。
- **纸纹**：只留在天空穹顶与 HUD/牌面等**正交 2D 平面**；3D 表面**禁用颜色噪声**，改用 `roughness` 低频微扰（振幅 ≤3%）+ 随距 mip 淡出（v1.1 §A.4）。P1 纯几何起步可**完全不放纸纹贴图**，纸感由雾色 + 哑光材质 + 平面层 HUD 兜底。
- **量化兜底**（v2 §4.3）：任一屏「同一屏内 ≥60% 面积仍是羊皮纸平面 / 纸雾 / 天空纸色」，达不到就退回 2D 层或加雾。

### 6.5 数据源硬约束（v2 §3.4 / R1，最高优先级的工程对接警告）

**参数表只能从 `ipa` + `hint` 派生，严禁读取 `js/config.js` 的 `length` / `tone` / `color` 字段作为几何依据。**

`config.js` 文件头已明确：`length:"长"/"短"` 与 `tone` **仅作 A/B 两侧视觉分组键**（`is-long` / `is-short`），不再承载长短音语义；`color` 由 `tone` 派生，也只是分组色。实证反例（逐字）：

```js

```

照抄会**长短圆唇整体做反**并与 D1 三宝石语义冲突。建议 #31 加最小对立一致性断言：`U10.lip.protrusion > U09.lip.protrusion`、`U32.voice.voiced===true && U31.voice.voiced===false`、`U22.voice.voiced && !U21.voice.voiced`。

- **D5 前后的一致性护栏变化**：v2 §3.7 原要求「主色、口型、标志性道具必须与 `Uxx.webp` 一致」——**D5 后放宽为「`unit` 绑定 + `ipa`/`hint` 语义 + 主色体系一致」，标志性道具/外轮廓不再强制**。若真要改某个标志造型，需重开该 `Uxx` 的过审流程（D5 影响面），**P1 不触发**。
- **一致性护栏仍保留**：`sym` 作稳定键（绝不用 `displayIpa`，config.js 文件头 D-4）；每个 3D 精灵出图与 2D 立绘**并排过审**，防 M1「同一骨架」滑向「换色贴纸感」（v2 R9：四组参数至少 2 组跨音素显著不同）。

### 6.7 防泄题（C3 在精灵 / 环境层的复述）

声音可视化环境（v2 M3）、三层预告（M5）、镜像闸门（M8）在判定完成前**只读音频包络 + `commitT` 位置 + 圈数/位置 + 当前区 id + 玩家动作**，**严禁读 `gate.spoken` / `correctLateral` / `qType` / `hit`** 及派生参数；环境特效不得把答案画出来。`reduced` 下 M3 改由 HUD 一枚静态波形图标承载同一信息（信息不丢）。

## §7 可访问性（硬约束，引用已锁分级）

沿用 `A11Y-TIER: Standard（本轮底线）→ Comprehensive（下一轮 3D 目标）`（v1.1 附录 2 / §0.6）。UX 规格（design-strategist `hud-ux-spec.md`）须显式引用此分级。P1 视觉层落地点：

- **色弱安全**：三车 / 车道对错**不靠红绿**（现状 `is-long #1f618d` 蓝 / `is-short #b03a2e` 红本就不是红绿）；kingdom 清浊红/绿**必须叠加形状冗余**（长音侧双横线 / 短音侧单点；清音侧实线 / 浊音侧波纹）+ 位置 + 方向箭头 + 明度差 ≥30%。protan/deutan/tritan 模拟下三车、车道、对错、小地图玩家点仍可辨。
- **动敏**：§2.6 全部动效纳入 `reduced` 开关，默认跟随 `prefers-reduced-motion`。
- **字号 / 对比度下限**（2D 平面层，不进 3D）：主数值 ≥20px、HUD 标签 ≥14px、路牌 IPA ≥26px（`.sign.on-lane .ipa` clamp 下限 16px→**20px** 并对路牌设屏幕空间最小尺寸）、小地图标注 ≥12px、quiz 选项 ≥16px、触控目标 ≥44×44px；正文 ≥4.5:1、大字 ≥3:1、非文本图形 ≥3:1。
- **输入 / 读屏 / 光敏**：全部操作键盘 + 触屏可达；`#live.sr` aria-live 保留；禁 >3Hz 全屏闪烁；3D canvas 有等价文本描述、小地图有「下一门在左前方」文本等价（Comprehensive 目标）。
- **低配分层降级**（不是砍功能）：L2 全效果 / L1 中（关动态阴影、DPR≤1.5、粒子减半、远景静态）/ L0 回退 2D 伪透视；**任何档位不得删减或缩小**小地图、路牌预告、圈数、进度条、combo、quiz 卡片可读性，不得缩小触控热区与字号。每个 3D 机制都有 2D/静态等价物（v2 §6.3）。
- **听障视觉冗余**：沿用 v1.1 附录 3，**不纳入本轮**，登记为下一轮需用户 + 设计侧共同拍板的独立议题，本文不擅自定义。
