## §1 「全龄精致」可执行判据

### 1.1 一句话定义

> **精致 = 结构清晰 + 材质可信 + 光影有据 + 动效有分寸 + 信息有序。它与「复杂度」「写实度」「暗黑度」无关，因此不存在按年龄降级的理由。**

回到用户原始诉求「卡丁车 / 赛道 / 游戏界面 UI 都能更精致美观」：卡丁车吃 §1.2 的①③，赛道吃⑤⑥，UI 吃②④。**六维判据就是把这句形容词拆成可验收的数字。**

### 1.2 六维判据（含可量化阈值）

| # | 维度 | 可执行判据（验收阈值） | 对应诉求 | 掉档的表现 |
|---|---|---|---|---|
| ① | **轮廓剪影精度** | 三车手在 **24px 高纯黑剪影**下两两可辨率 100%；每个主体由 ≥3 个结构特征构成（如高顶行李架 / 上翘尾翼 / 弧形尾鳍），负空间（轮拱、尾翼间隙、帽檐与头之间）≥ 包围盒 12%；轮廓不得是单一圆润团块 | 卡丁车 | 靠配色区分三车；250px 下看不出差别 |
| ② | **材质层次** | 每个主体 **≥3 且 ≤5 层**材质分区（基底 / 嵌线 / 箔印 / 宝石 / 柔光）；相邻层 `roughness` 差 ≥0.15、明度差 ≥8%；禁止「单一平涂 + 一层描边」 | 卡丁车 / UI | 平涂 + 一层黑边；或 6 层以上堆料发噪 |
| ③ | **光影与 AO** | **单一暖主光 + 1 柔补光 + 接触 AO**；接地处 / 凹槽 / 部件交界 AO 覆盖率 ≥80%；硬高光点 ≤1 个/主体；阴影柔边过渡带 ≥2px @375px；**禁止全屏 bloom / 多光源硬高光** | 卡丁车 / 赛道 | 塑料高光点、无接地阴影、bloom 糊白 |
| ④ | **动效克制程度** | 镜头抖动 ≤2–3px @375px 且无 >30Hz 分量；UI 入场 ≤0.35s 且弹性过冲 ≤8%；单帧位移 ≤屏宽 3%；循环动画周期 ≥1.2s；**所有动效可整体归零**（复用 `reduced`） | 游戏界面 UI | 果冻弹跳 / 每次答对全屏彩带 / 高频闪 |
| ⑤ | **色彩饱和度带** | 主体色 HSV **S ≤45%**（羊皮纸/石灰/木/墨蓝天然低饱和）；三宝石点缀 S 55–75% 且**屏幕占比 ≤8%**；禁止 S>85% 色块 >2% 面积；全屏收敛在 S 0–75%、V 0.35–0.96 | 赛道 | 糖果色大面积；或全场灰暗到只剩黑白 |
| ⑥ | **细节密度梯度** | 近层 0–12m 密度 100%、中层 12–45m ≤40%、远层 >45m ≤10%（剪影化）；**密度随距离衰减、不随年龄衰减**；每屏留白 ≥15%；单个 HUD 卡装饰元素 ≤3 个 | 赛道 / UI | 远近一样碎（摩尔纹）；或为「照顾低龄」把细节全砍 |

配套的可执行检查：① 把三车缩到 24px 黑剪影做辨识盲测；② 用取色器抽检主体 S 值与宝石占比；③ 375px 实机录屏逐帧看动效峰值位移；④ 三档距离各截一屏数细节单元数量。**四条都能出「过 / 不过」，不是形容词。**

### 1.3 为什么同一把标尺能同时被小学六年级和初中生接受

1. **年龄差异在「题材偏好」和「信息密度容忍度」，不在「做工精度」。** 11 岁和 15 岁对「这个东西做得糙不糙」的判断高度一致——两者都在同一套高水准游戏/动画/工业设计里长大，对塑料感、平涂、廉价高光同样敏感。反过来，「把造型简化成大圆团 + 糖果色」对初中生是**冒犯**，对小学高年级也**不被认为更友好**，只被认为是给更小的小孩看的。
2. **真正的分龄需求交给「分层」，不交给「降精度」。** 需要适配的是 HUD 信息密度与文案难度（属 UX / 文策渊域）：主层只放 3 项高优先信息、次层可展开；而形体/材质/光影的做工统一拉满。用「信息分层」解决认知负荷，用「做工不降级」解决全龄审美。
3. **现有 29 张成稿就是全龄精致的实证样本。** `a1/a2/a3/f` 同一张图里，小学生看的是精灵、城堡、探险家；初中生看的是元音四边形舌位坐标、辅音部位×方法矩阵、声带振动波纹对照表、罗盘与卷草纹的制图精度。**一张图两层信息、不降做工**——这正是 D1「知识感优先于可爱度」已经做到的事。v2 只是把它从纸面搬到空间，不换标准。
4. **「精致」不是「成人向」的同义词。** 精致指向工艺（剪影、材质、光影、动效），成人硬核指向题材与复杂度（写实 PBR、机械结构、暗色调、高信息密度仪表）。两者正交，§1.4 B 清单明确切断这条误读。

### M1 · 参数化精灵族谱（Polyspoon `createAsset(parameters)`）

- **视觉描述**：48 精灵不再各画各的，而是**同一套「精灵骨架」由发音四要素的几何参数驱动**：`唇形` → 口部环的开合/圆扁/前突；`舌位` → 体内一枚宝石菱形「舌冠」的高度/前后/卷曲度；`气流` → 体侧流线型鳍片的数量、走向与长度；`声带` → 喉部波纹环（浊 = 连续波纹，清 = 断开叉号）。例：`/s/` = 窄口 + 高前舌尖 + 三条细直线气流鳍 + 喉部叉号（与现有 `U31.webp` 小蛇一致）；`/uː/` = 前突小圆口 + 后高舌 + 长前向流线（与 `U10.webp` 吹蜡烛一致）；`/ŋ/` = 闭口 + 鼻腔上扬气流 + 软腭后位舌冠。**外形随发音特征变化，不是换配色贴纸。**
- **教学收益**：精灵形体本身就是发音要领的可视化——看形体可反推口型/舌位/气流/振动，把「背 48 个符号」变成「读 48 个形体」。更关键的是**最小对立对只差一个参数**（`s`/`z` 只差声带波纹、`i`/`ɪ` 只差张合幅度 + 舌高），差异被几何化，直接服务 `PAIRS_BY_MAP` 的听辨题。
- **依赖资产/参数**：Polyspoon procedural `.mjs` recipe + 注册参数表；§3.2 的语义部件与锚点；**48 行参数表（只从 `ipa` + `hint` 派生，禁用 `length`/`tone`/`color`，见 §3.4）**；现有 48 张 2D 立绘作为造型校验基准；消费方 pinned three（仅离线生成期，见 §3.6）。
- **实现复杂度**：中–高（1 套参数化骨架 + 48 行参数表 + 逐项过审），但**避免 48 次独立建模**；首版可只做 `config.js PHONEMES` 的 18 个音素，已完整覆盖四区杯赛。
- **375px 触屏可读性**：赛中精灵只以 ≤48px 徽章出现 → LOD 只保留**口部轮廓 + 舌冠位置 + 波纹有无**三个最大特征，细鳍片剔除；完整形体在收集图鉴 / 商店 ≥180px 展示。小屏下形体静止化（不播放 idle 动画），避免噪点。

### M2 · 静态 F 口腔剖面 → 可交互 3D 口腔剖面

- **视觉描述**：`f.webp` 升级为可旋转的半剖口腔：外壁羊皮纸质感半透，内部唇/齿/舌（尖·叶·根）/上颚/软腭/鼻腔/声带为可点选部件。选某音时四要素**联动**：舌冠滑到对应高度与前后、唇环开合/圆扁、气流沿一条发光宝石色路径从「肺」经口腔到唇外（或改走鼻腔）、声带亮起连续波纹或叉号。四要素各有一枚可切换的空白宝石色标注环（**文字在 2D 层**）。
- **教学收益**：把 F 图里「舌位高低前后坐标图」上的**一个点**变成可绕着看的空间关系；气流路径可视化解决「送气 vs 不送气 / 口腔 vs 鼻腔」的抽象难点；一次播放 = 四要素同时可见，正是 D1 §6 的立体重建。
- **依赖**：`f.webp` 作 2D 底版 / 回退；**与 M1 共享同一套发音参数表**；语义部件 `lip_ring / tongue_tip / tongue_blade / tongue_root / velum / vocal_folds / nasal_cavity / airflow_path`；标注锚点 `attach_label_*`；2D DOM 覆盖层承载文字与按钮。
- **实现复杂度**：高（1 个可参数化剖面模型 + 旋转/点选/联动），但**只有 1 个模型、可复用 48 次**；不做写实解剖（B6）。
- **375px 触屏可读性**：竖屏默认 3/4 侧剖视角；**自由拖拽改为「3 档预设视角」按钮**（正面 / 侧面 / 俯视舌位），部件热区 ≥44×44px，避免拇指遮挡；四要素标注全部在 2D 卡片层、不进 3D；reduced 下取消联动过渡，直接切换静态姿态。

### M3 · 声音可视化驱动环境（与听音题节奏同步，非背景特效）

- **视觉描述**：听音题音频播放的**那一刻**，环境跟着声音动：`气流` 参数驱动赛道两侧纸纤维/尘埃粒子的走向与速度（清摩擦音 = 细长直线，爆破音 = 短促爆发，鼻音 = 上扬）；`声带` 参数驱动护栏 / 灯笼 / 车身的**材质微震颤**（浊 = 低频连续颤，清 = 静止）；音量包络驱动天光极轻微明暗呼吸。**由音频包络驱动、随音频结束而收束**，不是常驻循环特效。
- **教学收益**：让「听」这件看不见的事在 3D 世界留下痕迹；清/浊、送气/不送气被放大为可观察的环境行为，形成**听觉 + 视觉的多感官冗余**，直接降低听辨难度。
- **依赖**：现有 `audio/*.mp3` + `js/audio.js` 包络；§3.3 发音参数表；现有 `render.js` 的 `view.particles` / `drawRibbon`；材质震颤 uniform；`reduced` 开关。**不新增模型。**
- **实现复杂度**：中（复用粒子系统 + 1 个 uniform）。
- **375px 触屏可读性**：粒子 ≤40、只在屏幕左右边缘 15% 带内出现（**不遮路牌 / 小地图 / 两车道**）；震颤 ≤1px；reduced 下完全关闭，改由 HUD 一枚**静态波形图标**承载同一信息（信息不丢）。
- ⚠️ **泄题红线**：效果只能由**音频包络**与当前区参数驱动，**绝不可读 `spoken` / `qType` / `correctLateral`**——否则环境会直接把答案画出来。

### M4 · 四区立体书式场景转场（方案甲下的折叠 / 翻页 / 层叠展开）

- **视觉描述**：四区切换不用淡入淡出，用「纸的折叠」：上一区沿一道烫金书脊**折起**、露出下层羊皮纸，下一区从纸面**依次立起**（护栏 → 建筑 → 地标 → 天空剪影），暗红虚线路径贯穿折线。三拍：折起 → 纸面显影 → 层叠展开。（v1.1 §D.2 的「纸卷擦除」深化为「折叠层叠」，更贴立体书母题。）
- **教学收益**：强化「四区在同一张藏宝图上」——「出发营地→元音城堡→辅音王国→进阶峰」从菜单文字变成**空间事实**；转场复用的暗红虚线路径本身就是 D1 的复习，不是装饰。
- **依赖**：`a1.webp` 四区布局；每区 ≤3 层远景剪影；**2D DOM/CSS 3D transform 覆盖层即可（方案甲下转场属平面层，不必 WebGL）**；`CACHE_TAG`。
- **实现复杂度**：低–中（纯 2D 层叠动画，零新增 3D 几何）。
- **375px 触屏可读性**：总时长 ≤1.2s、折线 ≤2 道；reduced 下改**静态纸面切换**（无翻页动效）；转场期间不显示任何题面信息。

### M5 · 跟车视角三层预告视觉层级（且不泄露听音题答案）

- **视觉描述**：
  - **L1 世界空间路牌**（3D billboard，分叉前 15–45m）：只给「前方有分叉 + 方向箭头 + 空白牌位」，牌面文字后期合成；有屏幕空间最小尺寸锁，不随距离无限缩小。
  - **L2 环境指示**：地面暗红虚线路径开始分叉、护栏宝石点渐密、地标方位偏移——传达「要准备选择了」的**空间预感**，不含左右正确性。
  - **L3 右上角小地图**：只显示该轮闭环赛道 + 玩家点（带朝向）+ 下一门**中性宝石点** + 圈数进度环，**不标注哪条车道正确**。
  - 三层共享同一套「预告语法」（烫金三角 + 墨蓝压线），信息粒度递进：**有岔 → 快到了 → 在哪**。
- **教学收益**：分层预告消除跟车视角「看不到全景」的方位焦虑，把注意力完整留给「听」；不泄露答案保证听辨题有效。
- **依赖**：现有 `#signs` / `render.js drawMinimap` / `#progress`；路牌 billboard；`buildGates` **仅取 `commitT` 位置**。
- **实现复杂度**：中（复用现有对象 + 统一层级与预告语法）。
- **375px 触屏可读性**：路牌 IPA ≥26px（on-lane clamp 下限提到 20px）、小地图 132×86；三层分别占**中部 / 下部地面 / 右上角**，互不遮挡；预告信息 ≤3 项/屏。
- ⚠️ **泄题红线**：三层在判定完成前**不得读 `correctLateral` / `spoken` / `qType`**；小地图下一门点必须是中性色，不得带 `is-long` / `is-short` 语义色。

### M6 · 48 精灵可收集 3D 立绘 + 六档稀有度用材质 / 箔印 / 光照

- **视觉描述**：收集图鉴里每个精灵是一尊可旋转的 3D 立绘（沿用 M1 骨架），站在羊皮纸菱形底座上。**六档稀有度不靠贴图徽章，靠材质工艺递进**：① 素纸浆 → ② 墨蓝嵌线 → ③ 局部烫金 → ④ 满烫金箔印 + 拉丝 → ⑤ 宝石镶嵌（红/绿/蓝按 D1 语义）+ 各向异性 → ⑥ 宝石内透光 + 单一追光 + 纸面投影光晕。**六档轮廓与尺寸完全一致**，不靠「变大变夸张」制造稀有感。
- **教学收益**：稀有度与「发音特征复杂度」绑定（卷舌 / 双元音 / 鼻音档位更高），激励从简单音走向难音；工艺递进本身是一堂材质课，也避开低龄化的「金光闪闪越大越稀有」。
- **依赖**：M1 参数化模型；**6 套共享材质 preset（零新增几何）**；`rarity_progress.webp` 仅作语义参考、不改图；现有身份卡作 2D 回退。
- **实现复杂度**：中（1 模型 × 6 preset）。
- **375px 触屏可读性**：图鉴单卡 ≥160px；六档在 160px 下靠**箔印覆盖率 + 有无追光**两级即可辨，细拉丝纹理仅在 DPR ≥2 启用；低配档退回 2D 卡面 + 静态箔印渐变。

### M7 ·【原创设想】发音地形：路面纹理编码发音部位

- **视觉描述**：四区路面纹理随该区音素的**发音部位**变化：camp（前元音）= 细密横向纹；castle（后元音 / 圆唇）= 同心圆弧纹；kingdom（双唇 / 唇齿）= 成对平行波纹；peak（齿龈 / 软腭 / 卷舌）= 螺旋 + 折线纹。玩家不看 HUD 也能从脚下纹理感知「这一区在练哪类口型」。
- **教学收益**：把抽象的「发音部位」变成**体感空间记忆**；视觉纹理 ↔ 口腔位置形成跨模态强化，是 D1「舌位坐标图」在赛道上的隐性延续。
- **依赖**：4 套程序化 pattern（shader 或可平铺矢量纹，**零新贴图**）；`zone id → pattern` 映射。
- **实现复杂度**：**低**（1 个 pattern 函数 + 4 组参数，零新模型 / 零新贴图）。
- **375px 触屏可读性**：纹理频率 **≤8 周期/屏**（防摩尔纹 / 闪烁）；高速下随距离 mip 淡出为纯色（呼应 v1.1 §A.4 纸纹原则）；reduced 下完全静态。

### M8 ·【原创设想】最小对立对镜像闸门

- **视觉描述**：分叉闸门做成左右两片**几何完全镜像**的立体书页，只在**一个「差异部件」**上不同——`s`/`z` 只差喉部波纹环有无，`p`/`b` 只差声带振动，`i`/`ɪ` 只差口部张合幅度，`n`/`ŋ` 只差舌冠前后 + 气流上扬角度。差异部件用同一枚宝石色高亮，但**不高亮哪一侧是答案**。
- **教学收益**：把「最小对立对」这个概念**建筑化**——学生看到「两扇门几乎一样、只差一处」，正是听辨题要抓的核心；比任何文字讲解都直观。
- **依赖**：M1 参数表 diff 驱动的可参数化闸门；`gate.pair` 的 unit 对；**不读 `correctLateral`**。
- **实现复杂度**：中（1 个可 diff 的闸门 recipe）。
- **375px 触屏可读性**：差异部件 ≥24px、置于闸门**上半部**（不被车遮挡）；两侧信息量严格相等、明度对称。

### M9 ·【原创设想】波波队长 / 小 Q 双角色讲解层 3D 化

- **视觉描述**：`f.webp` 里两位探险家（波波持放大镜、小 Q 圆脸卷发）以**纸片人立牌（standee）**形式出现在教学 / 图鉴页——方案甲允许的 2D 平面层 + 轻微视差，不建 3D 模型；用指向手势联动 M2 的剖面部件。比赛中收缩为 HUD 头像 + 车尾挂件（沿用 v1.1 §C.2）。
- **教学收益**：保留播客「双角色对话式」的教学人格，让 3D 知识场景不冷冰冰；同一角色在「讲解 / 竞速」两形态间连续存在，是跨站世界观的黏合剂。
- **依赖**：`f.webp` / `cover.webp` 的既有角色形象；2D standee（**符合平面层全 2D**）。
- **实现复杂度**：低。
- **375px 触屏可读性**：立牌只在教学 / 图鉴等**非竞速页**出现，绝不占赛道视野；HUD 头像 ≥44px。

## §3 Polyspoon 程序化资产对接规格

> 以下事实来自**主理人已查证**：Polyspoon 是 AI 驱动的开源 3D 资产社区 + 程序化 low-poly 生成器（2026-10 开源，2026-11-04 活跃）。输出：① **GLB**，含语义部件 / 锚点 / 声明的关节组，保留 rig 与 clips；② **程序化 `.mjs` 模块**，同步 `createAsset(parameters)` 从注册 recipe 生成，带 metadata / types / cleanup / rigid-pose API；③ **静态快照 `.mjs`**（异步 `createAsset()`，内嵌 GLB、非程序化）；④ **Generator source ZIP**（可编辑 TS）。procedural module 需消费方提供 pinned three；HTML 预览从 jsDelivr 加载 three、需联网。本文据此对接，许可证 / API 稳定性 / 离线可用性的复核项见 §3.8。

### 3.1 哪些资产适合参数化生成（按适配度分级）

| 级别 | 资产 | 理由 | 生成形态 |
|---|---|---|---|
| **高** | 48 音标精灵 | 同一骨架 + 4 组发音参数，天然参数化；48 张图各画各的正是要突破的上限 | procedural `.mjs` → 导出 GLB 快照 |
| **高** | 三车手卡丁车变体 | 共用底盘，靠剪影参数（顶高 / 尾翼 / 尾鳍 / 轮距）区分（v1.1 §C.1） | procedural `.mjs` |
| **高** | 赛道道具阵列（护栏 / 灯柱 / 界碑 / 旗帜 / 宝石格） | 重复阵列 + 少量区参数（材质换色 / 高度 / 纹样） | procedural `.mjs` + instancing |
| **高** | 四区地标 | 同一「塔」骨架 + 区参数（城垛 / 双塔 / 星标 / 穹顶） | procedural `.mjs` |
| **中** | 路牌 billboard、菱形宝石徽章、镜像闸门 | 参数少但需 diff 驱动（M8）与空白牌位 | procedural `.mjs`（低参数） |
| **中** | 可交互口腔剖面 | **唯一**高精度结构、需精确解剖关系，但可复用 48 次（M2） | 手工建模 → GLB（不参数化几何，只参数化姿态） |
| **不适合** | `a1/a2/a3/f/cover`、B 系列 24 张、48 卡面、`rarity_progress.webp` | 平面成稿，不进 3D；**全部原样保留** | 保持 2D |
| **不适合** | 天空穹顶 / 远雾 | 8-bit 渐变 WebP 即可，无需几何 | 渐变图 |

### 3.3 发音四要素 → 几何参数 Schema + 映射表

**参数词表**（全部 0–1 归一化，除枚举与整数）：

```
lip.aperture      0..1   唇开合（0 闭 → 1 全张）
lip.rounding      0..1   圆扁（0 展 / 横 → 1 圆）
lip.protrusion    0..1   前突
tongue.height     0..1   舌位高低（1 高 → 0 低）
tongue.frontness  0..1   舌位前后（1 前 → 0 后）
tongue.curl       0..1   卷舌
airflow.mode      enum    continuous | burst | nasal | lateral
```

### 3.4 数据源硬约束（v2 最重要的工程对接警告）

**参数表只能从 `ipa` + `hint` 派生，严禁读取 `js/config.js` 的 `length` / `tone` / `color` 字段作为几何依据。**

`config.js` 文件头已明确：`length:"长"/"短"` 与 `tone` 在新簇里**仅作 A/B 两侧的视觉分组键（`is-long` / `is-short`），不再承载长短音语义**；`color` 由 `tone` 派生，也只是分组色。实证反例（逐字核对）：

- `U10: ph("U10", "u", "uː", "长圆唇", "短", "short", ...)` → `/uː/` 是**长圆唇**，却被标 `length:"短"`、`tone:"short"`、`color: 红`。
- `U09: ph("U09", "ʊ", "ʊ", "短圆唇", "长", "long", ...)` → `/ʊ/` 是**短圆唇**，却被标 `length:"长"`、`tone:"long"`、`color: 蓝`。

若照抄这三个字段生成几何，**长短圆唇会整体做反**，且与 D1 三宝石语义冲突。建议下一轮给参数表加一条最小对立一致性断言（如 `U10.lip.protrusion > U09.lip.protrusion`、`U32.voice.voiced === true && U31.voice.voiced === false`）——本文只提需求，脚本交 quality-lead。

### 3.5 GLB 与 `.mjs` 两种形态各自的适用场景

| 形态 | 特征 | **适用** | **不适用** |
|---|---|---|---|
| **GLB**（含语义部件 / 锚点 / 关节组，保留 rig + clips） | 静态单文件、免运行时生成器、可直接被 glTF loader 消费、可预烘焙 | **绝大多数运行时资产**：48 精灵发布快照、三车手、口腔剖面、四区地标、路牌、闸门 | 需要按参数实时变形 / 批量生成变体时 |
| **procedural `.mjs`**（同步 `createAsset(parameters)`） | 参数驱动、recipe 注册、metadata/types/cleanup/rigid-pose API；**需消费方 pinned three** | **离线 / 构建期**：批量生成 48 变体、A/B 试造型、六档材质批量套用、生成后导出 GLB | **浏览器运行时直接消费**（引入 three 依赖，突破「无构建 / 无 WebGL / ESM 静态站」现状） |
| **static snapshot `.mjs`**（异步 `createAsset()`，内嵌 GLB） | 单文件自包含、非程序化 | 单个资产的轻量分发 / 版本锁定 | 大批量（内嵌 GLB 体积膨胀） |
| **Generator source ZIP**（可编辑 TS） | 可改 recipe | 美术侧维护参数 schema、提交工程打包 | 交付产物 / 运行时 |

### 3.6 生成与消费分离（对「无构建静态站」的关键建议）

> **参数化 `.mjs` 只跑在离线 / 构建期，产出带语义锚点的 GLB 快照进静态站；运行时零 three、零联网、零构建。**

这样既拿到「参数化生成 48 精灵」的创新，又不破坏项目现状。**HTML 预览从 jsDelivr 加载 three、需联网，不得作为交付物或验收依据**，须以本地 GLB 预览为准（离线可用是 375px 触屏 / 教室弱网场景的硬需求）。此条与 #14 技术预研并行，最终由工程侧确认。

### 3.7 与现有 48 张 2D 立绘 / 48 卡面的共存与渐进替换（**本轮零替换**）

| 阶段 | 3D 形态出现在哪 | 2D 资产状态 |
|---|---|---|
| **本轮（v2）** | 只有规格与提示词，**不生成任何替换资产** | **唯一正式资产**；同时作为 3D 造型的**校验基准（golden reference）** |
| 阶段 1（下一轮 3D 首批） | 3D 精灵只作**附加**可旋转立绘，出现在收集图鉴 / 商店 / 教学页 | 比赛 HUD、路牌、卡面、小地图**全部继续 2D** |
| 阶段 2 | 车身 decal 提供「2D / 3D 缩略」切换 | 2D **永远保留**为低配回退与无障碍回退（§6.3 L0） |
| 阶段 3（可选） | 仅在「同一精灵 2D/3D 可辨识度」盲测 ≥90% 后，才考虑让 3D 成为主形态 | **任何阶段都不删除 2D 资产** |

**一致性护栏**：3D 精灵的**主色、口型、标志性道具**（`/s/` 蛇、`/uː/` 蜡烛、`/ŋ/` 打鼾国王、`/iː/` 微笑小姐）必须与对应 `Uxx.webp` 一致；每个 3D 精灵出图需与 2D 立绘**并排过审**，避免 M1「同一骨架」滑向「换色贴纸感」（§7 R9）。

### 3.8 落地前复核项（交 #14 技术预研顺带核对，本文不越权）

标准第三方依赖尽调，非对主理人查证结论的质疑：① **许可证与署名**（社区资产 / 生成物的商用与再分发条款，教学产品发布前必须明确）；② **API 命名与版本稳定性**（`createAsset(parameters)` / `rigid-pose` / recipe 注册格式以实际 release 为准，规格中的参数名是美术侧约定、需工程映射）；③ **离线可用性**（生成器与预览是否可完全本地运行）；④ GLB 中语义部件 / 锚点 / 关节组的**实际保留率**；⑤ 与 `CACHE_TAG` 缓存串的对接。

## §4 方案甲在「创新突破」下的边界

### 4.1 可加重 3D vs 必须守 2D

| **可加重 3D（不破纸感）** | **必须守住 2D 平面层** |
|---|---|
| 世界层的**几何与光影**：车体体积与剪影、护栏透视、地标层叠、镜像闸门、口腔剖面空间关系、路面发音纹理（M7）、气流粒子路径（M3）、参数化精灵形体（M1/M6） | 一切**承载符号 / 文字 / 判定信息**的表面：HUD、路牌牌面、小地图、quiz 卡片、IPA / 中文标注、编号牌、精灵徽章位、转场纸页（M4）、双角色立牌（M9）、稀有度文字 |
| 前提：**过 v1.1 §A.4 材质三原则**（纸纹只留天空/正交面、烫金=箔印几何、墨线=嵌线 AO）+ 纸雾收敛 + 单一暖主光 + §1.2 六维判据 | 理由：① 无字底版 / 后期合成硬约束；② 高速运动背景可读性（v1.1 §E）；③ **纸感的总开关就在平面层** |

### 4.2 一条判断规则（避免下一轮两边打架）

> **「凡是需要被『读』的，留在纸上（2D 正交层）；凡是需要被『绕着看』的，才进空间（3D 世界层）。」**

**操作化**：一个视觉元素若包含**任何文字符号、选择题选项、对错指示、数值，或需要精确辨读的图标** → 归 2D 平面层，不参与透视 / 雾 / 景深 / 镜头抖动；若它只需被感知**形状、体积、方位、运动或材质** → 归 3D 世界层，且必须过 §A.4 三原则 + 纸雾收敛 + §1.2 六维判据。**有争议时默认归 2D。**

**两个推论**（正是「创新突破 ≠ 全盘 3D」的证明）：
- 参数化精灵的**形体**是 3D，但菱形徽章里的**符号**是 2D；
- 口腔剖面的**器官**是 3D，但四要素**标注环的文字**是 2D。

### 4.3 三条红线 + 一条量化兜底

1. 不得引入镜面反射 / 污渍磨损 / 写实 PBR（§1.4 B1）。
2. 3D 元素不得遮挡或参与 HUD 文字（v1.1 §E.3）。
3. 不得因加重 3D 而取消纸雾收敛与留白 ≥15%。
4. **量化兜底**：若某屏「纸感」被质疑，以「**同一屏内 ≥60% 面积仍是羊皮纸平面 / 纸雾 / 天空纸色**」为准；达不到就退回 2D 层或加雾。
