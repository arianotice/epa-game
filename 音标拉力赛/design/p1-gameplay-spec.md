## 1. D3 · 听音选车道保真规格（3D 跟车视角下）

### 1.1 设计支柱与 MDA 定位

| 层 | 内容 |
| --- | --- |
| **Mechanics** | 听 `audio.playWord()` → 判断词对应的音素 → 选左 / 右车道 → `judge()` 用 `hitsLane(lateral, correctLateral)` 判定 |
| **Dynamics** | 第三人称跟车视角下玩家**看不到整条赛道**，分叉只能靠前方预告判断何时该决策；音频与空间预警形成节奏 |
| **Aesthetics** | 「靠耳朵赢」的胜任感（competence）+ 可预期的挑战（flow），不是「靠眼睛找答案」的视觉匹配 |

**支柱（不可漂移）**：`听音为准`。任何 3D 增强只能增加「**何时**需要决策」的空间信息，**不得**增加「**决策什么**」的内容信息。

### 1.2 3D 跟车视角带来的唯一合法变化

| 项 | 2D 全景现状 | 3D 跟车视角（本轮目标） | 是否允许改变玩法 |
| --- | --- | --- | --- |
| 可见赛道 | 整条环线一览（`render.js` 画完 `track.samples`） | 只剩车前方一段，分叉在视野外或视野边缘 | ❌ 不改玩法，只改**信息可达性** |
| 预告的作用 | 冗余装饰（`hud-ux-spec.md` R1 已诚实标注） | **必要导航**：告诉玩家「马上要选车道了」 | ❌ 不改玩法口径 |
| 小地图 | 冗余 | 必要（闭环进度 + 下一门中性菱形） | ❌ 只承载几何，见 §1.4 |
| 答案域 | `spoken` / `correctLateral` 只在 `audio.playWord()` 与 `judge()` | **同样只在** `audio.playWord()` 与 `judge()` | ✅ 零改动 |

> **关键推论**：3D 让预告从「冗余」升级为「必要」，但**必要性只体现在时间 / 空间预警**，绝不能借此把词、IPA、口型、正确侧搬上视觉层。这正是 `hud-ux-spec.md:53` 已设的「支柱漂移红线」。

### 1.4 答案零泄露 —— 沿用 H5 口径（逐字对齐，含 3D 扩展）

**H5 基准（`hud-ux-spec.md:485`）**：对 4 个门逐一检查 `g.spoken.word`、`g.other.word`、`g.left.word`、`g.right.word`、各 `ipa` / `displayIpa` **均不出现**在 `mm.textContent`、`mm.innerHTML`、所有后代的 `alt` / `aria-label` / `data-*`；且无 `data-lane` / `data-correct` / `data-side` / `data-answer` 属性。

**D3 口径（本轮锁定）**：

```
扫描串 s = #minimap.textContent
        + #minimap 后代所有属性值（alt / aria-label / data-* / title / src）
        + #minimap.innerHTML（补充证据，非唯一判据）
        + 83 词全表（allWords() 口径）+ 4 门各自的 word / ipa / displayIpa
        + 字段名集合：correctLateral / spoken / left / right / pairKey / qType / options / hit / answer / correct
断言：上述词面与字段名在「显示文本 + 属性值 + 键名」三个面零命中
```

| 细化条款 | 说明 |
| --- | --- |
| **不退回 `innerHTML`** | 双重含义：① **判据**不得退化成「只看 `innerHTML` 单串匹配」而丢掉 `textContent` + 后代属性值扫描（H5 原文把 `innerHTML` 纳入被扫描串，**保留为补充证据**）；② **渲染路径**不得重新引入 `innerHTML` 拼接答案域（`hud-ux-spec.md:84` 单向铁律：任何 HUD 生成路径，DOM `innerHTML` / canvas `fillText` / CSS `data-*` / `alt` / `aria-label` 都不得接触 `correctLateral` 与 `spoken`） |
| **3D 扩展** | 新增扫描面：3D 场景中所有 `Mesh` 的 `name` / `userData` 键名、世界空间路牌的材质贴图与文字纹理、小地图菱形 `userData`；同样零命中 |
| **单向铁律不变** | `correctLateral` 与 `spoken` **只允许**出现在 `audio.playWord()`（`race.js:436`）与 `judge()`（`race.js:213-262`）；判定后结果页可列（决策已结束，无决策价值） |
| **H6 键名口径** | `JSON.stringify(minimapModel())` 不含 `spoken\|correctLateral\|left\|right\|pairKey\|qType\|options\|displayIpa\|answer\|correct` 作为**键名**；`nextGate` 键集合精确等于 `{id,lap,line,distance,secondsTo}` |

### 2.1 六档语义与材质锚点（对齐 `RARITY_RANK` 与 v2 M6 / P8）

### 2.2 三维评分模型（教研可辩护 · 确定性 · 可复算）

**三个维度**（各 `0..3` 整数，取值越大越难）：

| 维 | 名称 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- | --- |
| **A** | **部位难度**（调音部位 / 器官的可见度与精细度） | 双唇 / 唇齿，外部可见、可对照镜子示范 | 常规齿龈 / 硬腭 / 软腭 / 声门，及基本单元音舌位 | 龈后 / 腭龈、齿间、卷舌、软腭鼻、舌侧、长元音紧圆唇、双元音双部位 | 复合调音：r-色彩央元音、centring 双滑、齿间 + 浊化协同 |
| **B** | **方法复杂度**（气流 / 时长 / 段数控制） | 单段稳态：塞音、鼻音、短元音 | 稳态延长或单纯摩擦：长元音、擦音、近音 | 双段协同：塞擦音、双元音、清浊浊化对立 | 三段连续滑动 / 塞擦 + 卷舌 / 齿间摩擦 + 浊化叠加 |
| **C** | **中国学习者习得难度**（L1 负迁移 / 范畴建立） | 普通话有近似、直觉可及 | 需微调（长短 / 松紧、送气→清浊映射） | 需建立新范畴（汉语无对应）或高频混淆 | 双重叠加难点（新范畴 + 高频替代 + 儿化 / 前后鼻音负迁移） |

**复合公式与权重理由**：

```
CI = A + B + 2·C        （CI ∈ [0, 12]，全整数，无浮点）
```

> **为什么 `C` 加权 ×2**：本项目是面向中国学习者的**教研**游戏，稀有度要激励「从简单音走向难音」（v2 `:185`），因此「学习者实际卡在哪」比「语音学上器官动了几处」更能代表教学难度。`A` / `B` 是语音学事实等权，`C` 是习得实证维度加倍。此权重是**设计建议，待用户 / 教研评审确认**（§6-1）。

**分档阈值（绝对阈值，非分位数；确定性、可逐条复算）**：

| CI | 档 |
| --- | --- |
| `0–3` | P |
| `4–5` | SR |
| `6–7` | SAR |
| `8–9` | HR |
| `10` | SSR |
| `11–12` | UR |

> **设计理论检查**：分布 `14 / 12 / 9 / 6 / 4 / 3` 严格**单调不增**（`P ≥ SR ≥ SAR ≥ HR ≥ SSR ≥ UR`），避免「高档比低档多」使稀有度失去意义与收集激励崩塌（初版曾出现 `SAR 12 > SR 8` 的**稀有度倒挂**，已通过重设阈值修正，见 §2.6）。

- **r / l（U36 / U42）**：同为 `C=3`（`r/l` 高频混淆 + 暗 `l` / 词尾 `l`），`CI=9`，同为 **HR**；**同档**便于 QA 断言这对经典混淆对不出现档位倒挂。
- **æ / ʌ（U04 / U06）**：低前 / 央元音属**基本舌位**（`A=1`）、单段稳态（`B=0`），难点在**感知混淆**（`C=2`）而非发音复杂度 → 同为 `CI=5`、**SR**。这是**两维正交**的必然结果：教研上「难听辨」不等于「难发音」。该对立已由 `PAIRS_BY_MAP.castle` 的 `ʌ / ɑ` 最小对立对承担，**不靠稀有度体现**。QA 不应期待二者进入最高档，但**应期待二者同档**。
- **双元音**：`B=2`（双段滑动）共通；关滑 `eɪ / aɪ / aʊ` 因汉语复韵母可及（`C=0`）落 `CI=4` **SR**；`ɔɪ / əʊ`（`C=1/2`）落 SAR / HR；centring `ɪə / eə / ʊə`（`A=3, B=3`，r-色彩双滑）落 `CI=10` **SSR**。**同为双元音、按习得可及性分层**，而非一刀切。
- **三元音说明**：48 音标权威表为「20 元音 + 28 辅音」闭集，**没有独立三元音 unit**。本文**不新增音素**（会破坏 48 闭集、`sym` 稳定键与 48 张资产）。三元音式连续调音难度由 centring 双元音 `ɪə / eə / ʊə`（`ɪjə / ɛjə / ʊwə` 三段滑动，`B=3`）与半元音 `w / j` 的过渡承载，落 **SSR**。此为**口径声明**，不是遗漏。
- **浊化梯度**（教研上最直观的一条递进）：`b(P,CI=2) → d / g(P,CI=3) → v / z(SR / SAR,CI=5/6) → ʒ(SSR,CI=10)`；清浊对 `p / b`、`f / v`、`s / z`、`tʃ / dʒ`（`CI 0/2`、`1/5`、`2/6`、`6/8`）**每对浊音均不低于清音**，可直接做最小对立一致性断言（呼应 `3d-tech-feasibility.md:433`）。
- **鼻音梯度**：`m(P,CI=0) → n(SR,CI=5) → ŋ(HR,CI=8)`，前后鼻音混淆由 `C=2/3` 承载。
- **松紧 / 长短对立**：`iː / ɪ`（SR / SR，`CI 4/5`）、`ʊ / uː`（SAR / SAR，`CI 6/7`）——`ɪ / uː` 因紧音 / 长音在 `A` 或 `C` 上各高 1，但**不跨档**，保证对立对在同一收集难度带内。
