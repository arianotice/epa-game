# 「点开始后卡丁车不显现」诊断报告 + 2026-11-10 用户拍板

> **文档性质**：team-lead 独立只读诊断 + 决策登记。**未改任何产品代码、未部署、未上线、未 commit**。
> **日期**：2026-11-10 · **触发**：用户「现在打开游戏，点击开始后还是不能让用户的卡丁车和其他 NPC 卡丁车显现出来，检查好代码是否有问题」。

---

## 0. 结论先行

**不是渲染代码缺陷。** 真实情况是两件事叠加：

1. **2D 拉力赛本身是好的**：三种本地入口（源码静态 HTTP、Vite dev 5173、Vite preview 4173）用真实 Chromium 完整走「关闭玩法弹窗 → 选跟读档 → 上赛道 → 倒计时结束进入 racing」，**玩家车 + 两辆 NPC 车均清晰可见**，HUD / 圈数 / 小地图 / 触屏键齐全，`pageerror / console_error / requestfailed` 全 0，里程正常推进（541→597）。
2. **用户期待的「3D 卡丁车」从未实现，且拉力赛从未部署上线**：
   - P0 是**技术可行性切片**，按规格只做「一个立方体 + FogExp2 纸雾 + 单一暖主光」，`probe.html` 实测画面就是一个孤立立方体（`boxes=1 / drawCalls=1`），**没有赛车模型、没有 NPC、没有 3D 赛道**。
   - 线上 `deploy.sh` 只 scp `音标大闯关/` 的 `index.html / js / css / assets/sprites / assets/audio/ph`，**完全不含 `音标拉力赛/` 目录**。线上访问 `/音标拉力赛/index.html`、`/js/main.js` 均返回 3076 B 的**大闯关首页**（Caddy SPA fallback 兜底 200 陷阱，正是长期登记的风险）。
   - 托管链接 `https://ipa-quest-27394.app.workbuddy.host/?sharecode=ZC5U2OSSQQ` 也是大闯关首页（3035 B），全文无 `音标拉力赛` / `hud-20261108` / `id="c"` 任一命中。

> 因此「点开始看不到卡丁车」更像**入口错配 + 功能未实现**，而不是 `render()` / `race.state.karts` 坏了。若用户点的是线上链接的「开始」，进入的是大闯关，本来就没有赛车；若打开的是 `probe.html`，看到的是立方体。**不要把「未实现」误报成「已实现的 bug」，也不要把「代码没坏」包装成「需求已满足」。**

## 2. 与「放行部署 + 上线 + commit」的冲突（必须先裁决）

用户已明确授权「放行部署 + 上线 + commit」，但当前直接执行会得到一个**用户不想要的结果**：

| # | 事实 | 后果 |
| --- | --- | --- |
| C1 | 3D 卡丁车 / 3D 赛道 / NPC 3D 模型**均未实现**，P0 只有立方体 | 上线后依然「看不到 3D 卡丁车」，用户诉求未解决 |
| C2 | `deploy.sh` 不含 `音标拉力赛/` | 即使跑部署，线上仍只有大闯关，拉力赛依旧 404/兜底 |
| C3 | 项目**无 git 仓库**（`fatal: not a git repository`） | `commit` 需先 `git init` + 首次提交；且须排除 `node_modules/`（9361 文件）、`.p0-build/`、`.workbuddy/` 等 |
| C4 | `deploy.sh` 用 `scp` 到 `ubuntu@192.144.226.216`，**交互式提示 SSH 密码** | 非交互环境无法代输密码，需用户本地执行或提供凭据/免密 |
| C5 | 用户上一轮拍板「保持源码 scp 同源」 | 两站须同级部署到同一 origin，否则共享 `localStorage['ipa-quest-v1']` 失效（CN-4/T3） |
| C6 | 长期硬约束：线上 Caddy 对不存在路径兜底 200 返回首页 | 发布后资源送达**必须**按逐字节 + magic + sha256 + Content-Type 非 `text/html` 复核，**不信状态码** |

> **质量门判定：CONCERNS（发布阻断）**。按 SOP「跳过质量门直接进下一阶段」是严禁行为；放行授权已收到，但需先确定**这次放行到底放什么**，否则等于把「没有 3D 卡丁车 + 拉力赛没部署」的状态原样推上线。
